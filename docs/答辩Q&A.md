# 答辩 Q&A 预演

> 按「技术 / 业务 / 落地 / 安全 / 数据」五类整理，评委可能追问的方向 + 建议回答口径。

---

## 一、技术类

**Q1：为什么用 RAG 而不是直接微调大模型？**
- 知识（产品卖点、价格、平台规则）频繁变动，微调成本高、更新慢；
- RAG 只需改 JSON 知识库即可实时生效，零训练成本；
- 检索结果可作为「命中证据」展示，话术可解释、可追溯。

**Q2：BM25 够用吗？会不会漏召回？**
- 中文电商咨询以短句、卖点词为主，BM25 + 字符 bigram 分词对这类场景已够用；
- 检索层是接口化的 `Retriever`，可平滑升级为向量检索（embedding + 向量库）或混合检索，不影响上层。

**Q3：大模型「幻觉」怎么控制？**
- 用 RAG 把检索到的产品事实塞进 prompt 做「上下文增强」，生成被事实锚定；
- 生成层有 `try/except` 降级，失败时自动转人工话术，不会让客服链路断掉；
- 后续可加「引用校验」：生成内容若偏离命中卖点，回退为模板话术。

**Q4：多轮对话上下文怎么维护？**
- `Conversation` 维护会话历史，`SessionStore` 按 session_id 存取（内存，生产可换 Redis）；
- 每轮把历史 + 漏斗阶段提示（`stage_hint`）一起喂给模型，驱动「推荐→讲解→挖需→促单」。

**Q5：岗位分流（售前/售中/售后）是怎么做的？**
- 意图关键词 → `INTENT_POST` 映射：推荐/对比/参数/使用→售前，优惠/物流/促单→售中，售后→售后；
- 规则透明、可控、零成本，后续可升级为分类模型提升准确率。

## 二、业务类

**Q6：这套方案和店小蜜、晓多等现成工具比，强在哪？**
- 现成工具多是「人工辅助 + 规则机器人」，本方案是「RAG + 大模型」的**自主接待**；
- 打通了「提问 → 检索 → 话术 → 回复」无人化链路，并直接替代千牛的人工分岗与转接。

**Q7：AI 话术真的能替代人工吗？转化率有保障吗？**
- 话术三要素（卖点 FAB + 对比 + 促单）由 prompt 固化，质量稳定、可复制；
- 秒回 + 无转接流失，是转化率的直接抓手；
- 定位是「AI 自主接待 + 人工兜底」，异常/投诉自动转人工，不硬接。

**Q8：满意度怎么保证？**
- 话术标准化，不随客服个人水平波动；
- 情绪安抚、售后场景有专门提示词（`stage_hint` 售后阶段：安抚 + 方案 + 挽单）；
- 后续可接入客户评分做 RLHF 反馈优化。

## 三、落地类

**Q9：怎么接入真实的京东/天猫/抖音店铺？**
- 统一网关 `/webhook/{platform}` + `PlatformAdapter` 适配层，各平台消息格式差异隔离在 Adapter；
- 京东侧已留 `JDAdapter` 骨架（鉴权/签名/回调 TODO），按官方开放平台文档补签名与消息解析即可；
- 淘宝用千牛/服务市场，抖音用抖店开放平台，接入方式同构。

**Q10：上线要多久？有什么风险？**
- 知识库结构化即可跑通，样例到正式数据只需替换 `data/` 三个 JSON；
- 风险主要在「平台接入的鉴权/合规」与「大模型稳定性」，前者按各平台规范补齐，后者用降级 + 监控兜底。

**Q11：成本怎么样？**
- 检索零成本；生成按 token 计费，用 `deepseek-v4-flash` 可进一步降本；
- 相比人力，边际成本趋近 0，且 7×24 在线。

## 四、安全类

**Q12：密钥和用户数据安全吗？**
- 密钥走环境变量/.env，已 gitignore，不进仓库；
- 会话仅存必要上下文，生产建议脱敏 + 定期清理 + Redis TTL；
- 用户输入在边界校验（平台代码、空文本快速失败）。

**Q13：会被 prompt 注入吗？**
- 买家输入是「数据」，通过分隔符/角色约束与系统指令隔离；
- 演示版已做基本隔离，生产需加注入检测 + 输出过滤 + 敏感词风控。

## 五、数据与评测类

**Q14：知识库数据从哪来？规模多大？**
- 当前 8 款样例产品 + 4 平台规则 + 10 条 QA，用于跑通链路；
- 正式数据可从小熊电器商品中心 / 客服话术库批量导入。

**Q15：怎么评估 AI 话术好坏？**
- 对齐赤兔名品三指标（接待量/满意度/转化率）做 A/B 对比；
- 话术维度：卖点覆盖、风格贴合、促单动作、响应时长；
- 可用 LLM-as-judge 或人工抽检打标，持续迭代 prompt 与知识库。
