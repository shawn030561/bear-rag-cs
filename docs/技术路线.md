# 技术路线说明

小熊电器 AI 智能客服 —— 基于 RAG 的话术生成系统

---

## 1. 整体架构

```
                        ┌──────────────────────┐
                        │     多轮对话管理       │
                        │  (会话历史 / 意图识别)  │
                        └──────────┬───────────┘
                                   │ 阶段提示（推荐/讲解/挖需/促单）
        ┌──────────────┐          ▼
买家咨询 │   意图识别    │   ┌──────────────────────┐
 ──────► │ (售前/售中/  │──►│     生成层 DeepSeek    │
        │  售后/对比…)  │   │  卖点(FAB)+对比+促单   │
        └──────┬───────┘   └──────────┬───────────┘
               │ 查询                  ▲
               ▼                       │ Top-K 产品 + 平台规则
        ┌──────────────────────┐       │
        │      检索层 BM25      │───────┘
        │  中文分词(字bigram)   │
        └──────────┬───────────┘
                   │
     ┌─────────────┴───────────────┐
     │ 产品知识库      │  平台规则库  │
     │ products.json  │ platform_   │
     │ (卖点/参数/     │ rules.json  │
     │  竞品/FAQ)     │ (优惠/售后/  │
     │                │  话术风格)   │
     └─────────────────────────────┘
```

## 2. 分层设计

| 层 | 职责 | 实现 |
|---|---|---|
| **数据层** | 产品知识、平台规则、样例咨询 | `data/*.json`，结构化、可替换 |
| **检索层** | 从知识库召回与问题相关的产品 | BM25 + 中文字符 bigram 分词 |
| **生成层** | 基于检索结果 + 规则生成话术 | DeepSeek（OpenAI 兼容接口） |
| **对话层** | 多轮上下文、意图识别、漏斗推进 | `conversation.py` |
| **应用层** | 可演示的 Web 界面 | Streamlit（三个 Demo） |

## 3. 核心流程（RAG）

1. **意图识别**：对买家咨询做关键词规则分类（售前推荐 / 产品对比 / 参数咨询 / 优惠 / 物流 / 售后 / 使用）。
2. **检索（Retrieval）**：BM25 对产品文档打分，召回 Top-K 个最相关产品；平台规则按当前接待渠道直接注入。
3. **增强（Augmented）**：把「产品卖点 / 规格 / 竞品对比 / FAQ」和「平台优惠 / 售后 / 话术风格」拼进 Prompt 上下文。
4. **生成（Generation）**：DeepSeek 按三要素（**卖点 FAB + 对比 + 促单**）生成贴合平台风格的客服话术。

### 为什么要 BM25 而非一开始就上向量检索

- 产品库规模小（几十~几百 SKU），BM25 对**关键词 / 品类 / 品牌 / 竞品名**的召回已经足够精准；
- **零外部依赖**、启动快、结果可解释，适合 Demo 快速跑通；
- 预留升级路径：数据量变大后可平滑切换为 **向量检索**（BGE 中文 embedding + 向量库），或 **BM25 + 向量 混合召回（RAG-Fusion）**。

## 4. 多平台适配策略

不训练四套模型，而是用「**一个模型 + 平台规则注入**」：

- 把京东/天猫/抖音/拼多多的**话术风格、优惠活动、售后政策、物流时效**结构化进 `platform_rules.json`；
- 生成时按当前渠道注入对应规则，模型自动切换语气（如抖音偏热情口语、京东偏专业可靠）；
- 平台规则可独立更新，**无需重新训练**，符合「多平台规则适配难」的痛点解法。

## 5. 多轮对话与漏斗管理

- 会话历史维护在 `Conversation` 对象中，生成时取最近 6 轮作为上下文；
- 意图识别给出「当前漏斗阶段 + 下一步动作」提示，驱动模型完成 **推荐 → 讲解 → 挖需 → 促单** 全链路；
- 意图识别当前用关键词规则，**后续可替换为模型意图分类**（更鲁棒、可覆盖长尾表达）。

## 6. 生产化升级路线

| 阶段 | 内容 |
|---|---|
| **MVP（当前）** | BM25 + DeepSeek + 规则意图 + Streamlit，可演示 |
| **v1.1 向量化** | BGE 中文 embedding + 向量库，混合召回提升长尾问题命中率 |
| **v1.2 评测体系** | 构建话术质量评分集（贴合度/卖点覆盖/促单意愿），自动化回归 |
| **v1.3 意图升级** | 模型意图分类 + 槽位抽取（品类/预算/人群），替代规则 |
| **v2.0 生产化** | 接入真实工单系统、知识库自动更新、人工兜底转接、多并发与成本监控 |

## 7. 性能与成本

- 单次话术生成：检索 < 10ms（本地 BM25），模型生成约 1–3s（`deepseek-v4-pro`，`max_tokens=2048`）；
- 可用 `deepseek-v4-flash` 换取更低延迟，用于高并发接待场景；
- 知识库更新零训练成本：改 JSON 即生效。
